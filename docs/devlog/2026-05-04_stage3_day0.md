## Stage 3 Day 0 の進め方

### 1. Stage 3 計画書の作成

Stage 3 を 7 トラックに分解した。

| ID | トラック | 内容 |
|---|---|---|
| A | TBD 解決 | 主人公 / 世界観 / 時の筆 / 真層など、VS 着手前に必要な決定 |
| B | 技術セットアップ | git init / Unity install / プロジェクト初期化 / GitHub Public |
| C | ADR 作成 | 技術決定記録 |
| D | VS スコープ確定 | 「何が動けば VS と呼べるか」の境界設定 |
| E | 時の窓プロトタイプ | URP + Stencil + シンボル UI |
| F | 主人公ヒーロービジュアル | PixelLab + Aseprite + Retro Diffusion |
| G | 第 1 ゾーン実装 | 仮ゾーン構築 + コアループ + NPC 配置 |

後半で `docs/STAGE3_PLAN.md` §10 に開発環境の使い分け戦略を追加した。ノート TOM は WSL2 / Windows GUI の両方を使う主軸、デスクトップ UJPVOG2 は重い Unity / Blender / shader 検証用として位置づけた。

### 2. A トラック `/spec` で TBD を解決

VS 着手に必要な範囲だけを確定し、世界観の根幹や真層の収束は早期確定しない運用にした。

#### 確定した重要事項

| 項目 | 決定 |
|---|---|
| 主人公 | 中性的・両読み可能、年齢は 10 代後半〜20 代前半の仮置き、silent protagonist |
| 主人公の動機 | 「ぼんやりと覚えている家族に会いたい」から始まる三層構造 |
| 主人公の真相 | ループを止めるために生まれた異物。最終盤で開示 |
| 異物原則 | 異物は主人公のみ。NPC は普通の住人 |
| 時の筆 | 古代の遺物。主人公は元から / 気づいたら持っている。史上主人公だけが使える |
| オープニング | 家のベッド開始、ドア前で時の筆に気づく、外に出ると朝日 + 風 + 静謐な街 |
| 含み演出 | D-3 / D-7 改 / D-6 弱版。真相を示唆しすぎない薄い違和感に抑える |
| VS 主要違和感 | 失われた家族の記憶を、過去から持ち帰る本 / 手紙 / 歌譜などに統合 |

#### 保留した項目

- 第 1 ゾーンの正式名
- 主要 NPC 1-2 人の具体設定
- 鳥の音の有無
- 衰退原因の具体描写
- 主人公の出身詳細
- 真層の収束パターン
- 観測者 vs 世界の創造主体

### 3. VS_SCOPE.md v0 → v0.2

`docs/VS_SCOPE.md` で、Stage 3 の Vertical Slice を「どこまで作れば VS と呼べるか」に分解した。Codex fast のレビュー 12 件を受け、コア体験・削減ライン・UI / セーブ境界を調整した。

特に重要な境界:

- VS は第 1 ゾーン + 過去踏込み + 持ち帰り + 現在反映のコアループを成立させる
- 赤シンボル (過去) は実装、白 / 青はグレーアウト予告
- オートセーブ必須、手動セーブはプレースホルダ可
- インベントリ / 進行ログは Stage 4 送り可
- 層 2 片鱗演出は 1 カットだけ入れる

### 4. ADR 作成と Codex レビュー反映

C トラックでは、技術決定を ADR として分離した。各 ADR は基本的に以下の流れで進めた。

1. Claude が v0 起草
2. Codex fast が A/B/C/D/E 形式でレビュー
3. ユーザー判断を挟み、妥当な指摘を全件 or 選別反映
4. ADR インデックス更新
5. commit

#### ADR 別の要点

| ADR | 主題 | 要点 |
|---|---|---|
| 0001 | Engine | Unity 6.3 LTS + URP を本線、Godot 4.6 は撤退候補 |
| 0002 | Time Frame Portal | URP + Stencil Buffer + Renderer Feature。Renderer Feature 責務と踏込み詳細を分離 |
| 0003 | Asset Pipeline | PixelLab / Aseprite / Meshy / Blender / AIVA / Suno / Stable Audio 等を用途別に整理、法務台帳へ接続 |
| 0005 | Time Management | 踏込み時の主従反転、常駐ヒエラルキー方式、ActionRecordStore、セーブ対象範囲 |
| 0006 | Save System | Newtonsoft.Json + `Application.persistentDataPath`、autosave 1 + manual 3 slots、atomic write、migration chain |
| 0007 | UI Framework | uGUI 採用。TextMeshPro / Unity Localization / Canvas Scaler / accessibility 設定と連携 |

ADR-0006 は Codex Linux 引継ぎ後に起草した。自己レビューで、アクセシビリティ設定が `SaveEnvelope` と `settings.json` に二重保存される衝突を検出し、スロット非依存の `settings.json` へ一本化した。

### 5. 法務 / 公開まわりの下準備

AI 主体個人開発を公開する前提で、次の 2 件をテンプレート化した。

- `docs/legal/asset_ledger.md`: AI 生成 / 購入 / 自作アセットの出所、ライセンス、商用可否、加工履歴を残す台帳
- `docs/legal/steam_ai_disclosure.md`: Steam 公開時の AI disclosure 草案

Stage 2 で確認した三段階公開モデル (GitHub Public → itch.io → Steam) に合わせ、GitHub Public で先行公開しても後から説明不能にならない粒度の記録を目指す。

## ミスと訂正

### 1. `feedback_anemora_no_premature_lockin` 違反: SPEC §3.3 第 4 層

Claude が、時の筆所有者が過去に複数いたかのような構造を仮置きした。これは「史上主人公だけが使える」「異物は主人公のみ」という方向と衝突し、世界観の核を早期確定しすぎるミスだった。

訂正:

- 時の筆を使えるのは史上主人公のみ
- 前任者 / 守り人のような特殊 NPC は置かない
- 主人公の異物性は最終盤まで伏せる

### 2. `feedback_anemora_no_premature_lockin` 違反: SPEC §4.2 老人アーキタイプ

Claude が「街の老人 = 語り手」「前任者 = 守り人」のようなアーキタイプを置いた。ユーザー指摘により、NPC は全員普通の住人であり、特殊役割を勝手に付与しない方針へ訂正した。

訂正:

- 第 1 ゾーン NPC は普通の住人 1-2 人
- 語り部 / 前任者 / 守り人は不採用
- NPC は主人公の異物性を説明する装置にしない

### 3. 含み演出議論での模倣リスク

Claude が「進撃の巨人型」の含み演出を字義通りに模倣する方向へ寄せかけた。ユーザーの clarify により、必要なのは具体演出の模倣ではなく、**後から見ると意味が反転するが、中盤では確定しない情報密度** だと再整理した。

訂正:

- 演出は D-3 / D-7 改 / D-6 弱版の薄い違和感に抑える
- 真相説明の直接信号を序盤に置かない
- 考察余地は残すが、答えを早出ししない
