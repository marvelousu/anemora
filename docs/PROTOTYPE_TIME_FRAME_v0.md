# Time Frame メカ プロトタイプ仕様書 v0.1

> **作成**: 2026-05-08 (機能確認用プロトタイプ)
> **目的**: 時の筆メカの操作感確認、設計仕様確定の前段
> **位置付け**: 第 1 章 VS 本実装の前に、操作感を実機で評価する小型プロトタイプ
> **背景**: 抽象論で進めた P1-P7 設計に「操作しづらそう」「窓の生成場所が難しそう」「実際見てみないとわからない」というユーザー懸念。プロトタイプで操作感を確認してから本設計を確定する方針。

---

## 1. 目的

時の筆 (Time Frame) メカの **操作感を実機で確認する**。本実装の前に、以下を評価する:

- 窓の描画が直感的か
- 窓内のオブジェクトとの干渉が分かりやすいか
- 過去/現在切り替えがスムーズか
- 操作全体がストレスなく流れるか
- 窓のサイズ/形状が任意に描けることの面白さ

---

## 2. 機能要件 (最小)

### 2.1 窓を描く
- **マウスドラッグで自由形状に窓を描画**
- ドラッグ中は描画パスが画面に表示される
- ドラッグ終了で窓が確定、内部に過去/現在が表示される
- 形状は閉じた多角形 / 自由曲線

### 2.2 過去/現在切り替え
- 窓内に表示する時代を切り替え
- 赤シンボル = 過去、白シンボル = 現在
- キー or ボタンで切り替え (例: Q/E キー)

### 2.3 観察
- 窓越しに過去/現在の世界を見る
- 窓の外は Niro が立っている **現在** の世界
- 窓内は選択された時代 (過去 or 現在) の同じ場所

### 2.4 干渉 (クリック)
- **窓内のオブジェクトをクリックで干渉**
- 干渉可能なオブジェクトは視覚的にハイライト
- クリックで Niro が手を伸ばす演出 + オブジェクトを操作 (動かす / 押す / 取る等)
- 干渉結果は窓越しに見える

### 2.5 窓を閉じる
- ESC キー or 右クリックで窓を閉じる

---

## 3. UI 要件

### 3.1 入力
- **マウス左ドラッグ**: 窓を描画
- **マウス左クリック (窓内)**: オブジェクト干渉
- **Q キー**: 過去 (赤シンボル) 表示
- **E キー**: 現在 (白シンボル) 表示
- **ESC キー**: 窓を閉じる

### 3.2 視覚フィードバック
- 描画中: パスを淡い色 (赤 or 白) で表示
- 窓確定後: 窓の境界を時代の色 (赤 / 白) で表示
- 干渉可能オブジェクト: 微かにハイライト
- Niro の手: クリック時に画面上に手の演出 (どの方向に伸びたかが見える)

---

## 4. シーン要件 (最小)

### 4.1 テストシーン
- **1 つの建物** (例: 倉庫 or 小屋)
- **インタラクト可能オブジェクト 1-2** (例: 木箱、扉)
- **過去 = 中世の活気** (建物が新しい、扉が開いている、近くに人物の影)
- **現在 = 衰退** (建物が古い、扉が閉まっている / 壊れている、人物なし)
- 窓を建物の前に開いて、過去/現在を切り替えて観察 + 木箱をクリックで動かす、扉をクリックで開閉、等のテスト

### 4.2 スコープ
- ストーリー要素は不要 (機能確認のため)
- 主人公 Niro のキャラ実装は最小限 (簡易立ち絵 / カプセル可)
- 環境美術は仮 (Tier 2 風の簡易シェード可)
- BGM/SE は不要 or 最小限

---

## 5. 評価基準

プロトタイプ完成後、以下を評価:

| 軸 | 確認ポイント |
|---|---|
| **描画の直感性** | ドラッグで窓が思ったとおりに描けるか? 形状の自由度は適切か? |
| **窓の生成場所** | 「どこに開けるか」を選ぶ操作がストレスにならないか? |
| **干渉の分かりやすさ** | 何が干渉可能か / 何ができるかが視覚的に分かるか? |
| **過去/現在切り替え** | スムーズに切り替えられるか? 認識が混乱しないか? |
| **操作感全体** | 5 分間プレイしてストレスなく操作できるか? |
| **面白さ** | 「過去を見て干渉する」ことに体験価値があるか? |

---

## 6. 制約

- **Tier 2 範囲内** (Stage 4 graphics-foundation 既存スタイル)
- **HD-2D 風** (3D 環境 + 2D 風キャラ)
- 既存 Anemora アセットを活用可 (なければ仮アセットで OK)
- 開発期間目安: 2-3 日 (Codex 実装、ユーザー確認込み)

---

## 7. 評価後の進め方

プロトタイプ確認後に決めること:

1. **窓の自由形状描画** が機能するか? UI 改善が必要か?
2. **クリック干渉** で第 1 章 T4 連鎖 (D の香料 → C の畑) が成立するか?
3. **複数窓 (G1)** を試すべきか? (1 つの窓で物足りないと感じるか)
4. **窓のサイズ自由** が「サイズ変更ギミック」(旧 P7) を不要にするか?
5. **窓越しの会話 (G7)** をテストすべきか? (アリアと窓越しに対話、Niro 特殊能力)
